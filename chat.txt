- **AI-партнёр (Ты):** Пишешь стратегию, архитектуру, ТЗ для Cline, проводишь ревью, держишь общую картину. Если идея слабая — говоришь прямо.

## 2. Структура проекта и память (ЗАКОН)
Любой проект в Makefab живет в `D:\Makefab\projects\<имя_проекта>`.
В корне проекта ОБЯЗАТЕЛЬНО должны быть 4 файла:
1. `BRIEF.md` (что делаем, для кого, критерии приемки).
2. `STATE.md` (текущий статус, что сделано, что дальше. Обновляется ПЕРЕД сбросом контекста).
3. `AGENTS.md` (кто работает над проектом).
4. `TASKS.md` (очередь задач).

## 3. Технический стек (Стандарт Makefab)
- **Frontend:** React (Vite) + TypeScript + Tailwind CSS (строго версия 3.4, так как v4 ломает конфигурацию).
- **Backend:** Python (FastAPI) + SQLAlchemy (SQLite для дева) ИЛИ Node.js (в зависимости от специфики графа, решим на этапе архитектуры).
- **Визуализация:** React Flow, D3.js или PixiJS.
- **Git:** Обязательные локальные коммиты после каждого крупного шага. Пуш на GitHub — вручную Данилой.

## 4. Правила безопасности и надежности (Критично!)
1. **Human-in-the-loop (Человек в цепочке):** Если ИИ-скилл (например, appsec-review) предлагает удалить важный код (например, инициализацию БД `init_db`) или изменить пути к файлам, ТЗ должно быть проверено Данилой. Мы не ломаем работоспособность ради «теоретической чистоты».
2. **Секреты:** Никаких дефолтных паролей и ключей в коде (`change-me` запрещено). Всё только через `.env`.
3. **Пути:** Перед созданием файлов всегда проверяй точный путь (например, `backend/app/core/config.py`, а не `backend/core/config.py`).
4. **CORS:** `allow_credentials=False` при использовании Bearer-токенов. Никаких `*` в методах и заголовках.

## 5. Требования к ТЗ для Cline
Каждое ТЗ должно быть строгим и компактным:
- **Цель:** 1 предложение.
- **Файлы для изменения:** Точные пути.
- **Шаги:** Пошагово.
- **Что НЕ трогать:** Явно перечислить критичные файлы.
- **Критерии проверки:** Что должно работать (сборка зеленая, кнопка нажимается).
- **При зависании:** Инструкция «Не исследуй — просто примени правки».

## 6. Контроль расходов (Экономия токенов)
Cline работает платно по API. Чтобы счет не рос как снежный ком:
- **Правило чистого листа:** Одна задача = один сеанс. Как только задача выполнена (например, «создана БД» или «добавлен эндпоинт») — нажимаем `/newtask` в Cline.
- **Не давай Cline читать мусор:** В проекте будет файл `.clineignore`, где перечислены `node_modules/`, `venv/`, `dist/`. Cline не должен тратить токены на их чтение.
- **Лимит контекста:** Если контекст сессии превышает 100k-200k токенов, мы обновляем `STATE.md` и начинаем новую сессию.

## 7. Набор инструментов (MCP и Skills)
У Cline установлены и настроены:
- **MCP:** GitHub (через PAT), Context7 (актуальная документация), Playwright (автотесты).
- **Skills:** `appsec-review` (аудит безопасности), `frontend-design` (качественный UI), `database-schema-reviewer` (нормализация БД), `webapp-testing`.
- **Правило скиллов:** Перед финальным коммитом Cline ОБЯЗАН прогнать код через `appsec-review` и `database-schema-reviewer`. Результаты скиллов нужно переводить на русский язык.

Личная CRM в виде визуального графа: карта контактов из Telegram,

🚫 Почему Telethon / Pyrogram — это игра с огнём
Использование юзерботов (библиотек вроде Telethon, которые работают от твоего имени через MTProto) — это прямое нарушение правил Telegram. 

Риск бана аккаунта: Telegram активно борется с юзерботами, и твой аккаунт (или аккаунт твоего клиента) могут просто заблокировать. 

Потеря доверия: Один бан — и пользователь потеряет всё: каналы, контакты, годы переписки. Для продукта, который строится на доверии, это фатально. 

✅ Telegram Business API — единственный безопасный путь
Это официальный механизм, где Telegram сам передаёт боту сообщения из личных чатов с явного разрешения пользователя. Аккаунт в безопасности, а пользователь в любой момент может отключить эту функцию в настройках. Бот при этом отвечает от имени человека, а не как отдельный бот. 

💰 Что с Premium: главный миф

python
import json
import os
from datetime import datetime
from sqlalchemy.orm import Session
from app.models.models import Person, Message, Group

MY_TELEGRAM_ID = "user708435728"

def parse_and_seed(db: Session):
    json_path = os.path.join(os.path.dirname(__file__), '..', '..', '..', 'result.json')
    with open(json_path, 'r', encoding='utf-8') as f:
        data = json.load(f)

    default_group = db.query(Group).filter(Group.name == "Входящие").first()
    if not default_group:
        default_group = Group(name="Входящие")
        db.add(default_group)
        db.commit()

    persons_added = 0
    messages_added = 0

    # Парсим чаты (берем по 100 последних сообщений)
    if 'chats' in data and 'list' in data['chats']:
        for chat in data['chats']['list']:
            if chat.get('type') != 'personal_chat':
                continue
            
            tg_id = str(chat.get('id'))
            name = chat.get('name', 'Unknown')
            
            person = db.query(Person).filter(Person.telegram_id == tg_id).first()
            if not person:
                person = Person(telegram_id=tg_id, first_name=name)
                person.groups.append(default_group)
                db.add(person)
                db.commit()
                persons_added += 1

            msgs = chat.get('messages', [])[-100:] # Обрезка до 100
            for m in msgs:
                if m.get('type') != 'message': continue
                text_raw = m.get('text', '')
                if isinstance(text_raw, list):
                    text_str = "".join([t if isinstance(t, str) else t.get('text', '') for t in text_raw])
                else:
                    text_str = str(text_raw)
                
                if not text_str.strip(): continue

                new_msg = Message(
                    person_id=person.id,
                    text=text_str,
                    date=datetime.fromisoformat(m.get('date')),
                    is_from_me=(m.get('from_id') == MY_TELEGRAM_ID)
                )
                db.add(new_msg)
                messages_added += 1
        db.commit()

    # Парсим контакты (добавляем тех, кого не было в чатах)
    if 'contacts' in data and 'list' in data['contacts']:
        for c in data['contacts']['list']:
            phone = c.get('phone_number')
            if not phone: continue
            person = db.query(Person).filter(Person.phone_number == phone).first()
            if not person:
                full_name = f"{c.get('first_name', '')} {c.get('last_name', '')}".strip()
                person = Person(first_name=full_name, phone_number=phone)
                person.groups.append(default_group)
                db.add(person)
                persons_added += 1
        db.commit()

    return persons_added, messages_added

```python
import json
import os
from datetime import datetime
from sqlalchemy.orm import Session
from app.models.models import Person, Message, Group

MY_TELEGRAM_ID = "user708435728"

def parse_and_seed(db: Session):
    # Путь к result.json (он лежит в корне проекта, на уровень выше папки backend)
    json_path = os.path.join(os.path.dirname(__file__), '..', '..', '..', 'result.json')
    
    if not os.path.exists(json_path):
        return "Ошибка: файл result.json не найден по пути " + json_path

    with open(json_path, 'r', encoding='utf-8') as f:
        data = json.load(f)

    # Создаем группу по умолчанию
    default_group = db.query(Group).filter(Group.name == "Входящие").first()
    if not default_group:
        default_group = Group(name="Входящие")
        db.add(default_group)
        db.commit()

    persons_added = 0
    messages_added = 0

    # 1. Парсим чаты (только личные, берем последние 100 сообщений)
    if 'chats' in data and 'list' in data['chats']:
        for chat in data['chats']['list']:
            if chat.get('type') != 'personal_chat':
                continue
            
            tg_id = str(chat.get('id'))
            name = chat.get('name', 'Unknown')
            
            person = db.query(Person).filter(Person.telegram_id == tg_id).first()
            if not person:
                person = Person(telegram_id=tg_id, first_name=name)
                person.groups.append(default_group)
                db.add(person)
                db.commit()
                persons_added += 1

            msgs = chat.get('messages', [])[-100:] # Обрезка до 100 последних
            for m in msgs:
                if m.get('type') != 'message': continue
                
                text_raw = m.get('text', '')
                if isinstance(text_raw, list):
                    text_str = "".join([t if isinstance(t, str) else t.get('text', '') for t in text_raw])
                else:
                    text_str = str(text_raw)
                
                if not text_str.strip(): continue

                new_msg = Message(
                    person_id=person.id,
                    text=text_str,
                    date=datetime.fromisoformat(m.get('date')),
                    is_from_me=(m.get('from_id') == MY_TELEGRAM_ID)
                )
                db.add(new_msg)
                messages_added += 1
        db.commit()

    # 2. Парсим контакты (добавляем тех, кого не было в чатах)
    if 'contacts' in data and 'list' in data['contacts']:
        for c in data['contacts']['list']:
            phone = c.get('phone_number')
            if not phone: continue
            
            person = db.query(Person).filter(Person.phone_number == phone).first()
            if not person:
                full_name = f"{c.get('first_name', '')} {c.get('last_name', '')}".strip()
                person = Person(first_name=full_name, phone_number=phone)
                person.groups.append(default_group)
                db.add(person)
                persons_added += 1
        db.commit()

    return f"✅ Успешно! Загружено новых контактов: {persons_added}, сообщений: {messages_added}"

# Задание: API-эндпоинт для графа и вывод реальных данных во фронтенд

**Рабочая директория:** Строго `D:\Makefab\projects\links`.

**Цель:** Создать API-эндпоинт для получения графа (узлы и связи) из БД и настроить React Flow на загрузку этих реальных данных вместо моков.

**Шаги:**

**Часть 1: Бэкенд (Python/FastAPI)**
1. В папке `backend/app` создай файл `api.py` (эндпоинты).
2. В `api.py` напиши GET-эндпоинт `/api/graph`, который:
   - Подключается к БД.
   - Берет всех `Person`, у которых есть `telegram_id` (это те, с кем есть чаты).
   - Ограничивает выборку первыми 50 людьми (чтобы браузер не завис от 3000 узлов, позже сделаем пагинацию).
   - Формирует ответ в формате React Flow:
     - Массив `nodes`: центральный узел "Я" (id: "me", type: "default", position: {x: 0, y: 0}), и узлы для людей (type: "default", position: генерируется случайно).
     - Массив `edges`: связи от "me" к каждому человеку.
   - Возвращает JSON: `{"nodes": [...], "edges": [...]}`.
3. В `backend/main.py` подключи этот роутер (через `app.include_router`).

**Часть 2: Фронтенд (React/TypeScript)**
4. В папке `src/api` создай файл `graphApi.ts`. Напиши функцию `fetchGraphData()`, которая делает `fetch('http://localhost:8000/api/graph')` и возвращает результат.
5. Открой `src/App.tsx`. Измени его так, чтобы данные загружались из API:
   - Добавь стейт `const [nodes, setNodes, onNodesChange] = useNodesState([]);` (изначально пустой) и аналогично для `edges`.
   - Добавь `useEffect`, который при монтировании компонента вызывает `fetchGraphData()` и обновляет `nodes` и `edges` через `setNodes` и `setEdges`.
   - Если данные грузятся, показывай на экране текст "Загрузка графа...".
   - Убедись, что стили для узлов (круги) применяются.
6. Запусти сборку `npm run build`.

**Критерии проверки:**
- Бэкенд (`uvicorn main:app --reload`) отдает JSON по адресу `http://localhost:8000/api/graph`.
- Фронтенд (`npm run dev`) при открытии показывает реальный граф: в центре ты, а вокруг — люди из твоей базы Telegram.
- `npm run build` проходит без ошибок.
